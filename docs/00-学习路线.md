> 8 本、约 2960 页、4 个彼此独立的方向。**不要按文件夹顺序读**——那是四条线混在一起。

## 二、它们不是一条线：四条依赖链

```
① 数据与 ML 底座
   [1] PDSH ──┬─→ [2] MLCK（配方集，长期当手册）
              ├─→ [7] DLF（金融策略）
              ├─→ [6] RLF（强化学习）
              └─→ [3] NLP ──→ [4] LLM Serving

② 金融理论
   [5] FTP（无套利/鞅定价）──→ [7] DLF（把模型用到策略上）
                            └→ [6] RLF（把定价当环境）

③ 系统与性能
   [8] C++ ──────────────→（读 [4] 的性能章节时更顺）

④ 交叉点
   [5] 的蒙特卡洛 + [8] 的 C++      = 定价引擎
   [1][2] 的 pandas/sklearn + [7]  = 可回测的策略
   [3] 的文本特征 + [4] 的推理优化  = 能上线的 NLP 服务
```

**关键判断：**

- `[1]` 是全部的地基，其余 7 本都默认你会 pandas 和 sklearn。
- `[5]` 和 `[7]` **不是同一件事**：`[5]` 讲"价格为什么是那个数"，`[7]` 讲"用历史数据赌方向"。
  两本都要读，但**先读 `[5]`**，否则 `[7]` 里的回测、风险、仓位管理只能照抄。
- `[8]` 与其余 7 本几乎不重叠，是纯技能支线，不读也不影响理解别的书。
- `[4]` 最新（2026）也最容易过时：读的时候以"方法"为主、"框架 API"为辅。

## 三、三条路线，选一条当主线

### 路线 A｜量化研究 / 策略（想用 ML 做交易）

> 主线：`[1] → [5] → [2](选) → [7] → [6]`　约 130 小时

终点：能独立完成"数据 → 特征 → 模型 → 回测 → 风险评估"，并说清策略在什么假设下失效。
不读 `[3] [4] [8]`。

### 路线 B｜AI / LLM 工程（做应用、平台、Agent）

> 主线：`[1] → [2] → [3] → [4]`　约 120 小时

终点：能部署推理服务并做性能调优，能搭一条可上线的文本流水线。
不读 `[5] [6] [7] [8]`。

### 路线 C｜量化开发 / 基础设施（偏工程，金融为背景）

> 主线：`[8] → [1] → [5] → [4](性能章)`　约 140 小时

终点：能用 C++ 写正确的定价器，能解释推理服务瓶颈在哪。
不读 `[3] [6] [7]`。

> 三条路线都要读 `[1]`。时间只够一本，就读 `[1]`。

## 七、怎么读（比读什么更重要）

1. **先图后字**：技术书 60% 的信息在图和代码块。先扫目录 + 图，再决定哪节精读。
2. **代码必须自己敲**：照抄跑通一次，然后**合上书重写**。这一步决定你是"看过"还是"会"。
3. **每章一个问题**：读完写一句"这章解决了我哪个具体困惑"，写不出来说明白读了。
4. **概念卡片要合并**：同一个概念在 8 本书里出现多次（`martingale measure`、`cross-validation`、
   `KV cache`），合并成一张卡，而不是记八遍。
5. **允许跳**：2960 页里约 40% 是重复内容。跳读不是偷懒，是分配注意力。

> **版本坑先知道**（各书导读书卡里都有完整清单）：
> PDSH 写于 NumPy 1.x / sklearn 0.19 时代，`np.float`、`sklearn.cross_validation`、`df.append`
> 全部已移除；Hilpisch 两本用 TF 2.13 + `keras.optimizers.legacy`；DLF 用 MT5 取数；
> LLM Serving 的 vLLM 不支持 Windows。
